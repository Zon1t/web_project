## T1. 홈 식사팟 상태 표시 (A)

**배경:** 홈 '오늘의 식사팟'은 '내가 참여하지 않은 모집중·일정 확정' 팟만 보여서, 팟이 있는데도 "없어요"가 뜨는 경우가 있다.

**수정 파일:** `static/js/components/party-main.js`, `static/css/party-main.css` (필요하면 `today-meal.js`의 개수 계산)

**요구사항**
1. 끼니 탭(점심/저녁)별로 목록 API 결과 **전체**를 쓴다. (`/api/parties/list`는 FINISHED·DELETED를 이미 뺀다)
2. 정렬: ① 참여 가능 ② 참여 중(`joined=true`) ③ 참여 불가. 같은 그룹 안에서는 시간 빠른 순.
3. 참여 불가 이유를 **글로** 표시하고 흐리게:
   - `FULL` → '정원 마감', `CLOSED` → '모집 마감'
   - 내가 같은 날짜·끼니의 다른 팟에 이미 참여 중 → '이미 점심 식사팟 참여 중' (참여 가능 팟도 이 경우 3그룹으로)
4. 카드는 항상 눌러서 상세로 갈 수 있다. [참여] 버튼만 비활성. 참여 중이면 [식사팟 보기].
5. 최대 4개. 더 있으면 [전체 보기 (N)] → `party-list.html?date=오늘&mealType=탭값`
6. 빈 상태 문구: "열린 점심 식사팟이 없어요. 직접 만들어 밥친구를 모아 보세요" + [식사팟 만들기]

**완료 기준:** 참여 중인 팟·마감 팟이 홈에 보이고 이유가 글로 나온다. 5개 이상이면 4개 + 전체 보기. 키보드로 카드 이동·진입 가능.

## T2. 없는 식당 → 등록 후 자동 복귀 (B + A)

**배경:** 식사팟 만들기에서 식당 검색 결과가 없으면 "일치하는 식당이 없어요"만 나온다. 등록하러 가면 입력값이 사라진다.

**수정 파일:** `static/js/pages/party-create.js` (A), `static/js/pages/restaurant-register.js` (B). 백엔드 변경 없음.

**흐름**
1. (A) 검색 결과 0건 → 목록에 `'○○'은(는) 아직 등록되지 않았어요` + **[식당 등록하고 이어서 만들기]**
2. (A) 누르면 `sessionStorage['sseukbap.partyDraft']`에 `{date, mealType, time, capacity, memo, savedAt}` 저장 →
   `restaurant-register.html?name=검색어&returnTo=party-create` 로 이동
3. (B) 등록 화면: `name` 파라미터로 이름 칸 미리 채움. `returnTo=party-create`면 등록 성공 후
   `party-create.html?restaurantId={새 ID}&restore=1` 로 이동 (지금은 식당 상세로 이동함, 337번째 줄 근처)
4. (A) `restore=1`이면 저장값을 되살리고(30분 지난 값은 무시) 즉시 삭제. 식당은 `restaurantId`로 고정(기존 기능).
5. `returnTo`는 허용 목록(`party-create`)만 받는다. (외부 주소로 이동 금지)

**완료 기준:** 없는 식당 검색 → 등록 → 복귀 시 식당이 선택되어 있고 날짜·끼니·시간·인원·방 설명이 유지된다. 그냥 등록 화면에 들어가면 기존 동작 그대로.

## T3. 아이디 = 회사 이메일, 닉네임 12자 (C + DB)

**배경:** 아이디를 회사 이메일로 통일하고 닉네임은 자유롭게(2~12자). 사내망 인사 시스템 조회는 불가하므로 **도메인 제한**으로 대신한다.

> **2026-11-25 구현 시 변경 (C):** 아이디를 없애지 않고 **아이디 + 회사 이메일을 따로** 받는다. 가입은 둘 다 필수(이메일은 @samsung.com만), 로그인은 **아이디 또는 이메일** 둘 다 된다. `/api/auth/check-id`는 그대로 두고 `/api/auth/check-email`을 추가했다. 비밀번호는 아이디와 같으면 안 된다(기존 규칙). 이메일이 없는 기존 회원은 `emailRequired: true`로 계정 설정의 이메일 등록 안내를 받는다. 아래 설계 중 'LOGIN_ID 자동 생성', 'check-id 대체', '라벨 회사 이메일'은 적용하지 않았다. 상세는 `API_SPEC.md` 1장.

### 설계
- 로그인 키를 **`MEMBER.EMAIL`** 로 바꾼다. (이미 UK 있음) `LOGIN_ID`는 내부용으로 남기고 새 가입자는 이메일 앞부분 기반으로 자동 생성(중복 시 숫자 붙임, 20자 이내).
- 이메일 규칙: 앞뒤 공백 제거 + 소문자, `@samsung.com`만 허용 (`EmailPolicy`에 도메인 검사 추가, 허용 목록은 `application.yml` 설정값).
- 닉네임: 2~12자, 중복 금지 유지.

### DB (`docs/sql/10_email_login.sql` 새로 + `01_ddl.sql` 반영)
- **`NICKNAME VARCHAR2(30)` → `VARCHAR2(36 CHAR)`**: 지금은 30바이트라 한글 10자가 한계. 12자면 저장 오류가 난다.
- EMAIL은 기존 회원 때문에 **당장 NOT NULL로 바꾸지 않는다.** (전환 완료 후 별도 스크립트)
- 기존 계정 이메일 채우기: 더미·데모 계정(`user01~05`, `demo01~10`)에 `아이디@samsung.com` 형태로 일괄 UPDATE (이미 이메일 있으면 유지, WITHDRAWN 제외). `05_demo_data.sql`·`demo_reset.sql`에도 반영.

### 백엔드
- `SignupRequest`: `loginId` 제거(또는 무시), `email` 필수, `nickname` 2~12
- `AuthService.signup`: 이메일 도메인·중복 검사, LOGIN_ID 자동 생성
- `AuthService.login` + `LoginRequest`: 이메일로 조회 (`MemberRepository.findByEmail`). `LoginAttemptLimiter` 키도 이메일로
- **전환 기간:** 이메일이 없는 기존 회원은 기존 아이디로도 로그인 허용 → 응답에 `emailRequired: true` 추가
- 아이디 중복 확인 `/api/auth/check-id` → 이메일 중복 확인 `/api/auth/check-email` (인터셉터 예외 목록 `WebConfig` 수정)
- `NicknameChangeRequest`: 2~12
- `ErrorCode`: 도메인 불일치 오류 추가 (예: `INVALID_EMAIL_DOMAIN` 400 "회사 이메일(@samsung.com)만 쓸 수 있어요.")
- 비밀번호 찾기(`PasswordResetService`)가 이메일 기반이라 영향 확인

### 프론트
- `signup.html/js`: 아이디 칸 삭제, 이메일 필수 + [중복 확인], 닉네임 12자
- `login.html/js`: 라벨 '회사 이메일', placeholder `name@samsung.com`
- `emailRequired`면 로그인 직후 `account.html`의 이메일 등록으로 보내고, 등록 전에는 다른 화면 진입 시 다시 안내
- `account.js`: 닉네임 2~12 (상수 `NICKNAME_MAX`)
- 헤더·대화·참여자 목록에서 12자 닉네임 말줄임 확인

### 명세: `docs/API_SPEC.md` 회원가입·로그인·중복 확인·닉네임 변경 수정안 먼저 → 노션 반영(사람)

**완료 기준:** 새 가입은 @samsung.com 이메일로만 가능, 이메일로 로그인, 기존 계정은 이메일 등록 후 이메일 로그인, 한글 닉네임 12자 저장 OK, 시연 계정 로그인 OK.

## T4. 비공개 식사팟 (A + DB)

**배경:** 초대받은 사람만 들어오는 식사팟. 지금 초대 링크는 `party-detail.html?partyId=31`처럼 **순번이라 추측 가능**해서 비공개에 쓸 수 없다.

### DB (`docs/sql/11_private_party.sql` 새로 + `01_ddl.sql` 반영)
- `MEAL_PARTY.IS_PRIVATE CHAR(1) DEFAULT 'N' NOT NULL` + `CHECK (IS_PRIVATE IN ('Y','N'))`
- `MEAL_PARTY.INVITE_CODE VARCHAR2(32)` + `UK` (공개 팟은 NULL)

### 백엔드
- `MealParty`: `isPrivate`(YesNoConverter), `inviteCode`, `regenerateInviteCode()`
- `PartyCreateRequest`: `isPrivate`(기본 false). 비공개면 코드 생성 (`SecureRandom` 16바이트 이상 → URL-safe Base64)
- 목록·오늘의 팟·홈 조회: **비공개이면서 내가 참여자가 아닌 팟 제외** (`MealPartyRepository` 쿼리에 조건 추가)
- 상세 `GET /api/parties/{id}?code=`: 비공개 + 비참여자 + 코드 불일치 → **404 PARTY_NOT_FOUND** (존재 숨김)
- 참여 `POST /api/parties/{id}/members` 본문 `{inviteCode}`: 비공개면 코드 확인 (불일치 404)
- 초대 링크 API: 비공개면 `path`에 `&code=` 포함
- 코드 재발급 `POST /api/parties/{id}/invite-code` (방장 전용, 기존 링크 무효)
- 응답에 `isPrivate` 추가 (상세·목록·내 팟). 한 끼 한 팟·정원·행 잠금 규칙은 그대로
- 대화·따봉·랭킹 집계는 변경 없음

### 프론트
- `party-create`: [비공개: 초대받은 사람만] 토글 + 설명
- `party-detail`: 자물쇠 아이콘(SVG, 이모지 금지)·'비공개' 뱃지, 방장 메뉴 [초대 링크 복사]·[링크 새로 만들기]
- 링크로 들어오면 `code`를 기억했다가 참여 확인 창(`party-join.js`) → 참여 요청에 함께 전송
- 마이페이지·홈 '내 식사'에는 참여자에게 보임

### 명세: `docs/API_SPEC.md` 6장 수정안 먼저

**완료 기준:** 비공개 팟은 비참여자의 목록·홈에 안 보임, 코드 없는 링크·틀린 코드는 404, 맞는 코드면 상세·참여 가능, 재발급 후 옛 링크 404.

## T5. 용어 통일 (전원)

2-1 용어 사전을 화면 문구에 적용한다. 화면별 담당자가 자기 파일을 고친다.

| 위치 | 담당 | 고칠 문구 (예) |
|---|---|---|
| `landing.html`, `landing.js` | B | '점심·저녁 메이트', '동료와 식사팟을 꾸려요', '밥 친구', '작은 모임', '"같이 가요!" 한마디', `<meta description>`의 '동료·꾸리는' |
| `today-meal.js` (홈 '내 식사') | A | `○○ 자리가 비어 있어요` → `○○ 계획이 아직 없어요`, '같이 먹을 팟이 N개' → '참여할 수 있는 ○○ 식사팟이 N개 있어요', '[팟 보기]' → '[식사팟 보기]', 단독 '확정' → '참석 확정' |
| `today-meal.js` 빈 칸 버튼 | A | 모집 0개일 때 문구 "직접 만들어 밥친구를 모아 보세요" + 버튼 **[식사팟 만들기]** (지금은 목록으로 감) |
| `party-main.js` | A | '내 참여 확정' → '내 참석 확정', '같이 먹기', '다른 사람' → '밥친구' |
| 서버 시스템 메시지 (`PartyMemberService`, `PartyHostService`, `PartyService`) | A | '참여를 확정했습니다' → '참석을 확정했어요' 등 합쇼체 → 해요체 (또는 화면에서 변환) |
| `party-detail.js` 참여자 목록 제목 | A | '참여자 N / M명' → '밥친구 N / M명' |
| `mypage.js` | C | '확정 전' 뱃지 → '참석 확정 전', '함께한 식사팟' 카드(예정 팟 포함) → '참여한 식사팟' — **완료** (이미 반영돼 있었음, 빈 상태 문구 '밥친구'로 추가 수정) |
| `ranking.js` | C | 배너 '○월의 식당'(실제 기준은 최근 30일) → '요즘 뜨는 식당' 등 — **완료** (이미 '최근 30일 · 따봉 1위'. `ranking.html` 설명·로그인·가입 화면 '동료' → '밥친구') |

**완료 기준:** `grep -r "메이트\|꾸리\|한마디\|자리가 비어\|내 참여 확정" static/` 결과 0건.
